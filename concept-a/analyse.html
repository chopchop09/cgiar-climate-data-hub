Tier 3, part one

The country profile, as a structure

The country profile came up in the 10/08 discussion as a way of intersecting the use cases with geography, with the caveat that it cannot be done everywhere and a few priority countries would need to be chosen. What follows is the profile broken into six sections, with the data layers that would populate each one named, and the known obstacle for each stated.

No figures are shown, on purpose. No country-level figures have been compiled for this prototype, and inventing plausible ones would make the mockup impossible to review honestly. What is real here is the section list, the named data layers and the obstacles. The programme publishes a count of priority countries, 20 Tier 1 and 6 Tier 2, but the country names were not confirmed for this prototype, so no country selector is offered.

Two to four page country brief

Structure, source layers and known gaps. Country not selected.

Reading this as a work plan: sections one, two and three could be assembled from layers that already exist. Sections four and five need work that has not been resourced. Section six needs the expert directory, which does not exist.

Tier 3, part two

Portfolio analytics

The other half of this tier: not a brief about a country, but a view of the portfolio itself. These counts are computed from the eight projects catalogued on this prototype when the page loads, so they cannot drift out of step with the list on tier 1.

Projects in active development: . Counted from the portfolio, not typed in.

This is where the honest limit sits. Analytics over eight hand-catalogued projects is arithmetic, not analysis. The version worth building sits over the real project and results record, which means the tier depends on a data source this prototype does not have. Judge the idea, not the numbers.
