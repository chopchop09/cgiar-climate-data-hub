CGIAR Climate Hub

Three versions to review

The site you have already seen, plus two new interpretations of the feedback from the Climate Data Hub check-in of 10/08/2026. That feedback described the Hub as a stack of layers, and the description fits two quite different websites. Rather than pick one silently, both are built and working, so the choice can be made by looking.

"Static content. Publications, link to innovations, list of experts, news and events. Methods, manuals, tools. A layer on top that would allow a user to query about what CGIAR is doing about topic x, y, z. On top of that, analytics and country profiles. Then a dashboard that allows you to filter projects by keyword."

Every page in all three carries a bar at the very top for moving between them, so you cannot get stranded on one.

Open all three, in any order

The two concepts share their content, palette and stylesheet byte for byte, so a preference between them is a preference about structure rather than about styling. The current site is included because "neither, keep what we have" is a legitimate answer and should be easy to give.

What we would like you to answer

Sharper than "what do you think", and each answerable in a minute or two once you have all three open.

  1. Does either concept actually beat the current site? "Neither, fix the current one" is a real answer and the easiest one to lose if nobody asks for it.
  2. Open Concept A's front page. Is it too plain, or is that the point? It opens on information rather than imagery, which was the loudest single complaint about the gender platform.
  3. Search "drought" in Concept B. Three resources come back and no project at all. Is showing that gap so plainly a virtue or an embarrassment?
  4. Does anyone actually arrive wanting to browse? If nobody does, Concept A's first tier is a shelf nobody visits. If they do, Concept B makes them scroll past a search result to reach it.
  5. Should Concept A's tier map be public at all? It tells a visitor about our internal build sequence: useful for colleagues, arguably meaningless for a ministry official.
  6. Both concepts removed Ask the Hub and the Flyer Builder rather than showing them not working. Was that right, or does a non-working feature still earn its place by showing intent?
  7. Look at the experts collection in either concept. Six champions, labelled as not a directory. Is that the honest size of this function, or must it be a real directory to earn a place?

What is real, and what is not

Stated plainly, because the value of these prototypes depends on nobody mistaking a demonstration for a capability. This applies to the two concepts; the current site carries its own demonstration notices in place.

Real in both concepts

  • All 44 catalogued items and their sources. Thirty-three carry an outbound link, across 28 unique destinations, each either carried over from the v0.2 prototype or fetched on 10/08/2026.
  • The keyword search and every filter. Real scoring, entirely in your browser, no network calls, and nothing you type is sent anywhere.
  • Every count on the pages, computed from the data rather than typed, so the numbers cannot drift away from the lists.
  • The country brief's sections, its named source layers, and the obstacle recorded against each.

Deliberately not real

  • No country figures anywhere. Plausible placeholders would make honest review impossible.
  • No country selector. The programme publishes a count of priority countries, 20 Tier 1 and 6 Tier 2, but the names were not confirmed for these prototypes.
  • The experts list is six use-case champions, not a directory. No centre-by-centre list exists and no opt-out process has been agreed.
  • Search covers 44 hand-catalogued items, not CGSpace, Gardian or the Data Hub catalogue.
Neither concept includes Ask the Hub, on purpose. With no retrieval back end, a fixed sample answer draws comment about the answer rather than about the structure, which is the only thing these prototypes exist to test. It is still on the current site, where you can see the difference that choice makes. Working AI access to the Hub exists today via the Data Hub agent skills ↗.

One finding that may matter more than the choice

Search either concept for drought. Three resources come back, and no project in the portfolio matches at all. Drought was named on 10/08 as the topic recurring across more conversations than any other, and the discussion went as far as sketching a work stream on mapping and characterising drought for different crops and farming systems. Other single-word searches land in the same range: emissions returns five, livestock five, breeding three.

No architecture causes that thinness and none of the three can fix it. It points instead at the ingestion and tagging work discussed in the same meeting. On this evidence, that work decides whether any of these front ends is worth having.
